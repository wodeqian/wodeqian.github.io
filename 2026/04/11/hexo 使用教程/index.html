目录结构说明

根目录关键文件

_config.yml
站点全局配置：标题、副标题、URL、分页、部署方式、插件配置、菜单、代码高亮等。
⚠️ 不要和主题目录里的 _config.yml 混淆！
_config.butterfly.yml（推荐用法）
主题覆盖配置。
优先推荐：在根目录新建这个文件，把主题配置复制过来修改，升级主题不会丢失配置。
package.json
记录 hexo 版本、安装的插件（hexo-deployer-rsync 等）。
安装插件命令 npm install xxx –save 会写入这里。
db.json
Hexo 运行缓存，记录文章元数据。出现异常可以直接删除，hexo g 会自动重建。

scaffolds/ 脚手架模板

✅ 自定义：修改 post.md，以后新建文章自动带上你预设的 Front-Matter（tags、categories、cover 等）

source/ 【重中之重】源代码目录

Hexo 构建时，会处理 source 下文件输出到 public/
规则：下划线开头目录 _xxx 只会处理特定目录，其余直接忽略

source/_posts/
正式博客文章，hexo new 生成，构建后会展示在文章列表。

source/_drafts/

草稿，默认 hexo s、hexo g 不会打包发布
预览草稿：hexo s -d；草稿转正：hexo publish

source/xxx/（如 about、friends）

hexo new page xxx 创建的独立页面，生成 xxx/index.md
访问地址：域名/xxx/，适合：关于、友链、留言板。

source/images、source/js、source/static
自定义静态资源目录（自己手动新建）
放在这里的图片、js、json，执行 hexo g 会原样复制到 public
❗禁忌：不要命名为 source/_js，下划线目录静态文件会被忽略！
额外小知识点：
source/xxx.md 直接放在 source 一级，也会生成独立页面，等价 page，但是推荐统一用文件夹形式。
source/api/
放在这里的文件，会直接复制到 public/api/ 目录下 ，适合放接口文档、API 代码等。

themes/ 主题目录

所有页面样式、布局、html 模板都在这里

public/ 构建产物目录

执行 hexo generate / hexo g 自动生成
部署服务器、GitHub Pages 上传的就是这个文件夹内所有内容！
⚠️ hexo clean 作用：清空整个 public 文件夹，清除旧缓存文件。

node_modules

npm 下载的依赖插件，不要手动修改，不要上传 git。
高频命令对应目录回顾（联动你之前问的）
hexo new “测试文章” → source/_posts/测试文章.md
hexo new page about → source/about/index.md
hexo draft “草稿” → source/_drafts/草稿.md
hexo clean && hexo g → 生成 / 更新 public/

易于踩坑的目录规则（重点记）

文件夹名称以 _ 开头，Hexo 默认不输出静态资源
source/_static ❌ js 图片无法打包
source/static ✅ 正常打包
不要把静态资源放到 themes/xxx/source 之外自定义位置，路径容易错乱
public 是产物目录，不要直接修改里面文件！ 重新构建会全部覆盖
Windows 本地文件名大小写不敏感，Linux 服务器区分大小写，资源文件命名尽量小写英文
